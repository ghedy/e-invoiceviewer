# Segnalazioni di sicurezza

Non pubblicare in una issue fatture reali, messaggi PEC, dati fiscali, credenziali o dettagli sufficienti a sfruttare una vulnerabilità.

Per problemi di sicurezza, usare **Security → Report a vulnerability** nel repository GitHub, se il canale privato è abilitato. Se non è disponibile, aprire una issue che chieda un contatto riservato senza descrivere la vulnerabilità; il progetto non dispone di un indirizzo email pubblico dedicato.

Prima della pubblicazione il manutentore deve abilitare **Private vulnerability reporting** nelle impostazioni di sicurezza del repository.

Per errori funzionali usare una issue con dati inventati o anonimizzati. L’estensione non autentica PEC, firme digitali o sicurezza degli allegati.
